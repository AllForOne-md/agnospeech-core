AgnoSpeech — privacy-preserving hate-speech detection

The mechanism rewrites a post so a hate-speech detector still works on it while an authorship attacker cannot identify who wrote it.

The repository

github.com/AllForOne-md/agnospeech-core contains the mechanism and what is needed to run it.

Contents

  • The L1/L2/L3 privatization mechanism and the two engines that run it (below).
  • The evaluation harness: the HSD head, the authorship-attribution attacker, and the TO / utility / privacy metrics.
  • Data and reproduction: the Reddit board corpus, scripts/compute_results.py, and the fetch scripts for the public benchmarks.
  • The privatized data files (below), under privatized/.

Left out: the web dashboard / demo layer, the results viewer, notebooks, the knowledge base, and the experimental drop-ins that are not on the main path (the neural DP-grounded L3, the Captum rationale, the BIO tagger, and the NLI harm-check). About 50 files. The package imports cleanly, the three hard-rule conformance checks pass, and compute_results.py runs both engines. Install with pip install -e . (fast engine) or pip install -e ".[results]" (adds the zero-shot transformer engine).

The mechanism and its configurations

A configuration is a stopping point on one dial crossed with a choice of engine. The dial has four positions; each is a standalone transform of the raw post (and because L2's distillation already drops identifiers, "L1+L2" and "L2" give effectively the same output):

L0the raw post (reference)
L1 · Redactreplace direct identifiers (names, @handles, emails, phones) with typed placeholders
L2 · Distillkeep only the detector-salient harm span, drop the rest — this is where the privacy comes from
L3 · Rewritea readable reworded version: harm spans kept, other tokens masked or swapped

Two engines run the same dial. fast = TF-IDF + logistic HSD head (refit per corpus), regex L1, linear-attribution L2 — all-sklearn, minutes on CPU. zeroshot = cardiff twitter-roberta-base-hate head, GLiNER NER L1, occlusion L2 — no corpus-fit vocabulary, GPU-suited.

How to read the numbers

MetricMeaning
Utility ratioHSD macro-F1 on the privatized text ÷ on the raw text. 1.00 = the detector is unaffected.
Worst-case attackAuthorship-attribution accuracy (25 candidates), worst case over a static and an adaptive attacker. Chance ≈ 0.04; raw text = 0.46. Lower after privatizing = more privacy.
TOutility_ratio − privacy_ratio (the relative-gain form). Higher is better; range [−1, 1].

The attack / TO numbers are on the Reddit corpus (the only one with real authors), full held-out test split, n = 346, 25 authors.

Chance would be 0.04 (1 in 25). Raw text leaks the author 46% of the time; L2 (fast) cuts that to 22%.
Best configuration: L2 (distill), on both engines. fast @ L2 roughly halves the attacker (0.46 → 0.22) with no loss of hate-detection quality (utility 1.00) — the best trade-off (TO 0.52). zeroshot @ L2 is close (0.27 attack, TO 0.42) and also lossless on utility. L1 alone buys essentially no privacy; L3 is more readable but leaks more author signal than L2. Across six datasets both engines leave only 0–7% of hate un-privatized.

  • Reddit carries real (pseudonymous) author ids, so it supports a full authorship-attribution evaluation (25-candidate closed world) as well as utility. The numbers above come from these files.
  • Twitter (HateXplain, Gab rows dropped) is utility-only: it has hate labels but no author labels, so it supports the detectability side, not an attribution attack. An author-labeled Twitter corpus could be run through the same pipeline to produce an author-bearing file.

These are the recommended L2 configuration. The L1 and L3 variants, other corpora, and larger samples are one flag away (compute_results.py --cap N).
